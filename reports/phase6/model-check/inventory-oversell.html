Modeling assumptions
  • database default isolation: read-committed (PostgreSQL semantics, see docs/phase6/POSTGRES-ISOLATION.md)
  • a database statement is atomic unless it must wait for another transaction; waiting statements resume with their original snapshot
  • autocommit (root `db`) statements are single-statement transactions at the default isolation level
  • local computation is not a scheduling point; it is folded into the preceding transition
  • rows are read in primary-key order for LIMIT 1 (the declared programs and generated SQL both use ORDER BY the primary key)
  • tasks of different actors never share a transaction, connection or event loop; actors listed with the same process share in-process variables and crash together
  • a process crash rolls back open transactions and loses local state; committed data and performed external effects remain
  • actor A: relational query `findFirst` assumed to be `SELECT ... LIMIT 1`
  • actor A: no orderBy: the first row in primary-key order is taken
  • actor B: relational query `findFirst` assumed to be `SELECT ... LIMIT 1`
  • actor B: no orderBy: the first row in primary-key order is taken
