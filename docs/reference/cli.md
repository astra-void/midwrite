# CLI reference

Generated by reading `--help` of every subcommand of the release binary
built from the current tree on 2026-10-27 (`commitrift 0.1.0`, Phase 13
working tree, before any Phase 14 change). Only flags that binary accepts
are listed. `commitrift <command> --help` is authoritative for the binary
you have.

```text
commitrift <COMMAND>
  check        explain      ir          trace       report
  model-check  discover     schema      replay      init-replay
commitrift --version   →  commitrift 0.1.0
```

A legacy `crashproof` executable behaves the same and prints a
deprecation note on stderr.

## Exit status

| status | `check`, `ir`, `trace`, `report` | `model-check` | `discover` | `replay` |
| --- | --- | --- | --- | --- |
| 0 | clean | `NO_COUNTEREXAMPLE_WITHIN_BOUNDS` | no model counterexample | every case as its manifest expects |
| 1 | a diagnostic at or above `--fail-on` (`check`) | `COUNTEREXAMPLE_FOUND` | at least one model counterexample | a case did not match its declared expectation; with `--baseline`: a case changed between reproduced and not reproduced |
| 2 | usage, configuration or input error | invalid scenario (path of the field) or usage error | usage or input error | usage error; also when only the plan was printed (no `--allow-execution`) |
| 3 | some files could not be read or parsed (and no diagnostic reached the threshold) | `INCONCLUSIVE` or `UNSUPPORTED` | — | replay blocked (for example isolation unavailable); a case inconclusive, or with `--baseline` not executed |

Exit statuses of `replay` were read from `crates/commitrift-cli/src/replay.rs`.

## check

Analyze TypeScript sources and report potential partial-failure hazards.
Guide: [check](../user-guide/check.md).

```text
commitrift check [OPTIONS] [PATHS]...          PATHS default: .
```

| option | default | meaning |
| --- | --- | --- |
| `--format text\|json\|sarif` | `text` | output format ([output formats](output-formats.md)) |
| `--config <FILE>` | `./commitrift.json` if it exists (legacy `./crashproof.json`) | [configuration](configuration.md) |
| `--fail-on error\|warning\|info\|never` | `warning` | lowest severity that makes the command exit 1 |
| `--max-paths <N>` | 512 | paths analyzed per function |
| `--max-call-depth <N>` | 3 | levels of calls inlined from summaries (0 disables) |
| `--policy recommended\|strict\|audit` | `recommended` | which findings are warnings |
| `--baseline <FILE>` | — | findings in the baseline are reported but do not count toward `--fail-on` |
| `--write-baseline <FILE>` | — | record every current finding; exit 0 unless some file could not be analyzed |
| `-v`, `--verbose` | — | text output: also evidence and general limitations |

## explain

```text
commitrift explain [CODE]
```

Documentation for a diagnostic code, or the list of codes. The list shows
CP1001–CP1005, CP9001 and CP7001–CP7102; `commitrift explain CP7103` also
works. Catalog: [`docs/DIAGNOSTICS.md`](../DIAGNOSTICS.md).

## ir

```text
commitrift ir [OPTIONS] [PATHS]...
  --format text|json      (default text)
  --config <CONFIG>
```

Print the Effect IR derived from the sources.

## trace

```text
commitrift trace [OPTIONS] [PATHS]...
  --format text|json      (default text)
  --config <CONFIG>
  --finding <ID>          only this finding (fingerprint) or trace id
  --max-paths <N>         (default 512)
  --max-call-depth <N>    (default 3)
  --policy recommended|strict|audit   (default recommended)
```

The failure trace behind each finding. Static only. Format:
[Phase 3 trace format](../phase3/TRACE-FORMAT.md).

## report

```text
commitrift report [OPTIONS] <INPUT>
  --format html           (the only format)
  -o, --output <FILE>     default: standard output
```

Render a trace report (`trace --format json`) or a verification report
(`replay --format json`) as a self-contained, read-only HTML page.
`model-check` and `discover` render their own HTML with `--format html`.

## model-check

Bounded model checking of a scenario. Guide:
[model-check](../user-guide/model-check.md).

```text
commitrift model-check [OPTIONS] <SCENARIO>
```

| option | meaning |
| --- | --- |
| `--format text\|json\|html` (default `text`), `-o, --output <FILE>` | output |
| `--validate-postgres` | replay the counterexample on a private, disposable PostgreSQL (needs the server binaries); nothing runs without a counterexample |
| `--no-por` | disable partial-order reduction |
| `--dpor` | dynamic partial-order reduction (Phase 9); refused with an `always` invariant |
| `--source-dpor [stateful-sleep\|stateful\|stateless-sleep]` | source-set DPOR (Phase 10); refused with an `always` invariant or a context-switch bound; experimental |
| `--strategy bfs\|dfs` | search strategy when reduction is off |
| `--no-minimize` | report the first counterexample unminimized |
| `--no-timing` | omit wall-clock timings (byte-reproducible output) |
| `--max-steps`, `--max-states`, `--max-wall-ms`, `--max-in-flight <N>` | override `bounds.*` |
| `--profile-storage` | report the memory of the visited-state structures |
| `--fault-mode any\|in-flight` | which crash points are explored (`in-flight` needs `bounds.maxInFlight ≥ 1` and `bounds.maxCrashes ≥ 1`) |
| `--source-revision <REV>` | revision of the analyzed project to record in the report |
| `-v`, `--verbose` | text output: every modeling assumption |
| `--verify-source` | run the counterexample against the actors' original code (the scenario's `sourceVerification`); requires `--allow-execution` |
| `--harness <MANIFEST>` | source-harness manifest (default: `sourceVerification.harness`, relative to the scenario) |
| `--allow-execution` | authorize executing the application code named by the harness |
| `--source-repeat <N>` (default 1) | run the original code N times, each on a fresh database |

## discover

Candidates and scenarios from source; never executes application code.
Guide: [discover](../user-guide/discover.md).

```text
commitrift discover [OPTIONS] <ROOT>
```

| option | default | meaning |
| --- | --- | --- |
| `--contracts <FILE>` | `commitrift-contracts.json` in the root, if present | [contracts](../user-guide/contracts.md) |
| `--model-check` | off | model-check the synthesized scenarios (bounded) |
| `--emit-scenarios <DIR>` | — | write every synthesized scenario (model-check format) |
| `--hypothetical` | off | also build HYPOTHETICAL variants (a schema the application does not have); never findings about the application |
| `--source-dpor [MODE]` | sleep sets | source-set DPOR for model checking |
| `--max-candidates <N>` | 64 | candidates for which scenarios are built; the rest are static candidates |
| `--max-partners <N>` | 6 | other entries paired with one candidate |
| `--max-states <N>` | 200000 | distinct states per scenario |
| `--max-wall-ms <N>` | 60000 | wall-clock time per scenario |
| `--max-memory-bytes <N>` | — | approximate memory of one scenario's visited states |
| `--max-total-states <N>` | 5000000 | distinct states over all scenarios |
| `--max-worlds <N>` | 8 | Phase 15: initial worlds (rows and arguments) tried per actual variant, the synthesized one included; each further world changes one input relationship; `1` turns the search off ([world search](../phase15/FEEDBACK-GUIDED-SEARCH.md)) |
| `--all-worlds` | off | keep exploring worlds after a validated counterexample |
| `--explain-coverage` | off | text output: list every explored and unexplored world, every coverage gap and how each loop was bounded (also with `-v`) |
| `--entry <TEXT>` | — | only entries whose selector contains this text (repeatable) |
| `--labels <FILE>` | — | score the report against labeled entries |
| `--cache <FILE>` | — | cache extractions in this file |
| `--format text\|json\|html`, `-o, --output <FILE>` | `text` | output |
| `--no-timing` | — | reproducible output |
| `-v`, `--verbose` | — | also assumptions and rejected combinations |

With `--emit-scenarios <DIR>`, every candidate whose status is
`MODEL_COUNTEREXAMPLE` also gets `<scenario>.counterexample.json`
(`kind: "commitrift.counterexample"`, Phase 15): the world, rows,
arguments, assumptions, bounds, schedule, source fingerprint and the
commands to replay it.

## schema

```text
commitrift schema [OPTIONS] --file <FILE> <ROOT>
  --file <FILE>            the Drizzle schema module, relative to ROOT
  --migrations <SQL>...    migration files to apply to a disposable database and compare
  --allow-execution        required with --migrations (the SQL is executed on a private cluster)
  --format text|json       (default text)
```

Example (static, real output, first lines):

```text
$ commitrift schema fixtures/phase8/shop-app --file src/lib/db/schema.ts
table orders (binding `orders`, src/lib/db/schema.ts:3)
  id                       integer                      NOT NULL
  customer_email           text                         NOT NULL
  amount                   integer                      NOT NULL
  status                   text                         NOT NULL default Constant { value: Text("unpaid") }
  updated_at               timestamp                    NOT NULL default Expression { text: "now()" }
  primary key (id)
table payment_attempts (binding `paymentAttempts`, src/lib/db/schema.ts:13)
  id                       serial                       NOT NULL default Sequence { generated: "serial" }
  ...
  foreign key (order_id) → orders(id)
```

## replay

Run an explicitly authorized replay harness (directory with
`commitrift-replay.json`). Without `--allow-execution` only the plan is
printed. Guide: [source verification § replay harnesses](../user-guide/source-verification.md#single-request-replay-harnesses).

```text
commitrift replay [OPTIONS] <HARNESS>
  --case <CASE>               a case id, or a diagnostic code when exactly one case targets it
  --finding <ID>              only cases that target this finding
  --allow-execution           execute the harness's own code (required to run anything)
  --repeat <N>                each case N times, each from a fresh database (default 1)
  --allow-network             run without network isolation (the manifest must also declare "network": "allow")
  --keep-artifacts            keep the temporary database and logs
  --format text|json          (default text)
  --output <FILE>             also write the JSON report
  --baseline <FILE>           compare with a previous verification report of the same harness
  --regression-output <FILE>  write that comparison as JSON
```

## init-replay

Generate an editable replay-harness skeleton for one finding. Writes only
into `--output`; executes and installs nothing.

```text
commitrift init-replay [OPTIONS] --trace <FILE> --finding <ID> --output <DIR>
  --runtime node|bun          (default node: Node.js 22+ with tsc; bun: Bun 1.2+)
  --project <DIR>             the directory `commitrift trace` ran in (default .)
  --analyze <PATH>            paths to analyze, relative to --project (repeatable)
  --config <FILE>             configuration relative to --project
  --force                     overwrite the generated files (other files are never touched)
  --allow-incomplete          generate even for an incomplete trace
```

## Environment variables

| variable | used by | effect |
| --- | --- | --- |
| `COMMITRIFT_THREADS` (legacy `CRASHPROOF_THREADS`) | `check`, `trace`, `ir` | worker threads |
| `COMMITRIFT_PATHS` = `shared` \| `compact` \| `legacy` | `check`, `trace` | path mode (default `shared`) |
| `COMMITRIFT_PG_BIN` | runtime commands | directory of the PostgreSQL server binaries (else `postgres` on `PATH`) |
| `COMMITRIFT_REQUIRE_REPLAY=1` | test suite | a missing replay prerequisite fails a test instead of printing `SKIPPED` |
